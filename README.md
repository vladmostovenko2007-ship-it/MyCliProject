# Практичне заняття 13. Командний інтерфейс додатку

## Тема проєкту
Каталог персонажів (Тема 1).

## Архітектура
Проєкт розділено на три шари:
1. **Шар представлення (CLI):** Клас `CliFacade` та `ArgParser`. Відповідає за взаємодію з користувачем, читання вводу та вивід результатів у консоль.
2. **Шар бізнес-логіки (CORE):** Інтерфейс `ICommandStrategy` та його реалізації (`ListCharactersStrategy`, `AddCharacterStrategy`). Містить логіку виконання команд.
3. **Шар даних (DATA):** Клас-заглушка `FakeDatabase` для зберігання списку персонажів у пам'яті (замість реальної бази даних).

## Використані патерни проєктування
*   **Фасад (Facade):** Клас `CliFacade` приховує складність парсингу аргументів та пошуку потрібної команди, надаючи простий метод `ExecCommand`.
*   **Стратегія (Strategy):** Кожна дія (вивести список, додати) реалізована як окремий клас, що імплементує `ICommandStrategy`. Це дозволяє легко додавати нові команди, не змінюючи основний код.

## Список команд CLI
*   `list` — виводить список усіх доступних персонажів.
*   `add <ім'я>` — створює нового персонажа (наприклад, `add Гаррі`).
*   `help` — виводить довідку по доступних командах.
*   `exit` — завершує роботу програми.
